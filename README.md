# SuCheckAI

**VENTUREHACK 2026 · Open Innovation**

SuCheckAI — проект системы агроэкологического мониторинга, объединяющей портативный измерительный прибор на ESP32 и демонстрационную веб-платформу для работы с показателями поливной воды и информацией о рисках засоления почвы.

**Демо веб-платформы:** https://sucheckai-kz-demo.crazypixel01.chatgpt.site/

> **Текущий статус.** По сообщению команды, программные функции сохранения измерений, аналитики по заданным правилам, паспорта поля и экспорта отчёта прошли функциональное тестирование. Автоматическая Bluetooth-синхронизация прибора и сайта пока не подтверждена. Текущая аналитика основана на правилах, а не на обученной модели ИИ.

## 1. Проблема

Фермерам необходим доступный способ оперативно получать и сохранять показатели поливной воды и наблюдать за состоянием полей. Лабораторный анализ требует времени и ресурсов. SuCheckAI предназначен для предварительного полевого мониторинга и учёта результатов, **но не заменяет лабораторные исследования**.

## 2. Решение и основные функции

- **Аппаратная часть:** получение отдельных показателей водного образца с помощью датчиков, их обработка микроконтроллером и отображение на OLED-дисплее.
- **Веб-платформа:** ручной ввод и сохранение измерений, просмотр истории, работа с цифровым паспортом поля, региональная визуализация рисков, объяснение результатов на основе заданных правил и экспорт отчёта.
- **Важно:** TDS поливной воды и засолённость почвы — разные показатели. Измерение TDS воды не является прямым измерением засолённости грунта.

## 3. Аппаратные компоненты

В представленной концепции указаны:

| Компонент | Назначение |
| --- | --- |
| ESP32-WROOM DevKit V1 | Микроконтроллер |
| OLED SSD1306, 0,96″ | Отображение показаний |
| ADS1115 | Аналого-цифровой преобразователь |
| Датчик pH с BNC-интерфейсом | Измерение pH жидкого образца |
| TDS Meter V1.0 | Оценка минерализации жидкого образца |
| BME280 | Параметры окружающего воздуха |
| 18650, TP4056, MT3608 | Автономное питание |
| PETG, TPU, крепёж M3 | Корпус |

Точные подключения, версия прошивки, методика калибровки и наличие отдельного датчика температуры воды должны быть указаны в документации к **фактически загруженному** аппаратному коду.

## 4. Веб-платформа

Команда сообщила об успешной проверке следующих сценариев:

1. Ввод измерения, сохранение записи и повторное открытие после обновления страницы.
2. Изменение числовых показателей **и текста пояснения** при изменении входных значений.
3. Отображение данных в цифровом паспорте поля.
4. Экспорт отчёта для просмотра и печати.

Ручной ввод данных доступен в демонстрационном сценарии. **Автоматическую передачу показаний с ESP32 по Bluetooth не следует считать проверенной**, пока команда не продемонстрирует её на реальном устройстве.

Региональные показатели риска и демонстрационные значения не следует выдавать за результаты собственных полевых измерений. Для их использования в реальных агрономических решениях необходима проверка источников данных и методики расчёта.

## 5. Функциональная валидация

| Тест | Проверенное поведение | Результат по сообщению команды |
| --- | --- | --- |
| История измерений | Ввод → сохранение → обновление страницы → повторное открытие | Пройден |
| Аналитика на основе правил | Изменение значений → изменение показателя и пояснения | Пройден |
| Паспорт поля и отчёт | Просмотр данных поля → экспорт отчёта | Пройден |

**Ограничения валидации:** данные тесты подтверждают проверенные функции веб-приложения, но не точность физических датчиков, работу Bluetooth, научную обоснованность рекомендаций, рост урожайности или коммерческий спрос. При наличии приложите в `docs/` скриншоты тестов, использованные входные значения, ожидаемый и фактический результат, а также пример отчёта с пометкой «демонстрационные данные».

## 6. Архитектура

Подтверждённый сценарий работы с ручным вводом:

`Образец воды → показания прибора → ручной ввод на сайте → сохранение → интерпретация по правилам → паспорт поля и отчёт`

Этот сценарий **не означает**, что автоматическая связь прибора с веб-платформой уже работает. Реальные технологии сайта, способ хранения данных, протокол обмена и зависимости следует описать после загрузки соответствующего исходного кода.
